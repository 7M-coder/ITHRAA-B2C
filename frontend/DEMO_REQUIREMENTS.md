# متطلبات نظام إدارة الموارد البشرية والعُهد

> وثيقة نقل متطلبات وسلوك النظام إلى مشروع آخر. المتطلبات الوظيفية وقواعد العمل أدناه هي المرجع الأساسي؛ يمكن تكييف شكل الواجهات مع مكتبات المشروع المستهدف مثل Ant Design أو Lucide أو غيرها، مع الحفاظ على السلوك والهوية البصرية.

## 1. الغرض والنطاق

النظام نموذج عربي لإدارة بيانات الموظفين والرواتب والعُهد وإخلاء الطرف، موجه لمنشآت في المملكة العربية السعودية. يدعم RTL، ويعرض بيانات تجريبية قابلة للإضافة والتعديل أثناء تشغيل التطبيق.

النظام الحالي **Demo**: البيانات محفوظة في الحالة المحلية للتطبيق وتعود إلى البيانات التجريبية عند إعادة التحميل. ملف الرواتب CSV ملخص تحويل تجريبي، وليس ملف حماية أجور رسمي معتمداً من منصة مدد أو البنوك. لا تقدّم الواجهة ادعاءً بأن العمليات أو الحسابات اعتماد قانوني أو تكامل حكومي.

## 2. إرشادات التنفيذ للمشروع المستهدف

- افحص بنية المشروع ومكتبته الحالية أولاً، ثم أعد استخدام مكوناته وأنماطه قبل إضافة اعتماديات جديدة.
- حافظ على الحقول، قواعد التحقق، الحسابات، الحالات، وشروط تفعيل الأزرار الواردة هنا حتى لو اختلف ترتيب الواجهة أو مكوناتها.
- يجوز استخدام بدائل مكافئة للمكونات: Data Table أو Table، Modal أو Dialog، Dropdown أو Menu، وRecharts أو مكتبة رسوم موجودة في المشروع.
- استخدم أيقونات SVG أو مكتبة أيقونات المشروع مثل Lucide؛ لا تستخدم Emojis كأيقونات للواجهة.
- افصل منطق البيانات والحسابات والتحقق عن مكونات العرض حيث تسمح بنية المشروع بذلك.
- استخدم تواريخ ISO في التخزين (`YYYY-MM-DD`) واعرضها باللغة العربية السعودية (`ar-SA`). اعرض المبالغ بالريال السعودي (`SAR` / `ر.س`).

## 3. هيكل التطبيق والتنقل

التطبيق داخل غلاف رئيسي يدعم `dir="rtl"` على مستوى الواجهة كلها، ويتضمن قائمة جانبية، شريط حساب المستخدم، محتوى الصفحة، وتذييلاً يحمل اسم «إثراء الخير».

| المسار       | اسم الصفحة     | الوظيفة                                   |
| ------------ | -------------- | ----------------------------------------- |
| `/`          | لوحة القيادة   | مؤشرات الموارد البشرية والعُهد والتنبيهات |
| `/employees` | الموظفون       | قائمة الموظفين وإضافة/تعديل بياناتهم      |
| `/payroll`   | مسيرات الرواتب | حساب صافي الرواتب وتصدير CSV              |
| `/custody`   | العُهد         | إسناد العُهد ومتابعة حالتها حسب الموظف    |
| `/clearance` | إخلاء الطرف    | مراجعة الإجازات والعُهد قبل المخالصة      |

أي مسار غير معروف يعيد المستخدم إلى لوحة القيادة. تبقى القائمة قابلة للاستخدام على الشاشات الصغيرة، مثلاً بالتمرير الأفقي أو بقائمة قابلة للطي حسب مكتبة المشروع.

### حساب المستخدم في الشريط العلوي

- يعرض اسم المستخدم، دوره الوظيفي، وصورته الرمزية أو الأحرف الأولى.
- الضغط على منطقة الحساب يفتح قائمة منسدلة تحوي خيار «تسجيل الخروج».
- تغلق القائمة عند الضغط خارجها أو الضغط على `Escape`، ويظهر وضعها لقارئات الشاشة (`aria-expanded`, `aria-haspopup`).
- تنفيذ تسجيل الخروج الفعلي يعتمد على نظام المصادقة في المشروع المستهدف. إن لم يوجد نظام مصادقة، يبقى الخيار عرضياً ولا يوحي بأن جلسة حقيقية أُغلقت.

## 4. أنواع البيانات

### الموظف

```ts
type EmployeeNationality = 'سعودي' | 'غير سعودي'
type EmploymentStatus = 'Active' | 'Terminated'

interface Employee {
  id: string // معرف داخلي فريد
  fullName: string
  nationalId: string // الهوية الوطنية أو رقم الإقامة
  bankIban: string
  idExpiryDate: string // YYYY-MM-DD
  nationality: EmployeeNationality
  jobTitle: string
  basicSalary: number
  housingAllowance: number
  transportAllowance: number
  gosiRate: number // نسبة مخزنة من 0 إلى 100
  employmentStatus?: EmploymentStatus // الغياب يعامل كموظف نشط
  uncompensatedLeaveDays?: number // أيام إجازة غير معوضة عند نهاية الخدمة
}
```

### العهدة

```ts
type AssetType = 'سيارة' | 'لابتوب' | 'سلفة مالية'
type AssetStatus = 'Active' | 'Returned' | 'Lost'

interface Asset {
  id: string
  employeeId: string // يربط العهدة بالموظف
  type: AssetType
  description: string
  serialNumber: string // اختياري عملياً، وتقبل القيمة الفارغة
  assignedAt: string // YYYY-MM-DD
  status: AssetStatus
}
```

معرفات الموظفين والعُهد فريدة. عند إضافة سجل جديد، أنشئ معرفاً فريداً. احتفظ بالعلاقات عبر `employeeId` ولا تربط السجل باسم الموظف فقط.

## 5. إدارة الحالة والبيانات التجريبية

- يلزم مخزن مشترك للموظفين وآخر للعُهد، أو ما يعادلهما في إطار المشروع.
- عمليات الموظفين: جلب/تحميل البيانات التجريبية، إضافة موظف، تعديل موظف مع الحفاظ على معرفه.
- عمليات العُهد: جلب/تحميل بيانات تجريبية، إضافة عهدة، وتغيير حالتها.
- الصفحات تجلب بيانات Demo عند الحاجة إذا كانت القوائم فارغة. لا تستبدل بيانات مستخدم موجودة كلما دخل إلى صفحة.
- الحالة في النسخة الحالية ذاكرة مؤقتة فقط؛ لا توجد مزامنة خادم أو حفظ دائم. إذا كان المشروع المستهدف يوفر API أو قاعدة بيانات، يمكن توصيل المخزن بها دون تغيير قواعد العمل.

## 6. وحدة الموظفين

### قائمة الموظفين

- تعرض جدولاً يحوي: اسم الموظف، رقم الهوية/الإقامة، الجنسية، المسمى الوظيفي، الراتب الأساسي، تاريخ انتهاء الوثيقة، وإجراء التعديل.
- يظهر Badge مختلف للسعودي وغير السعودي باستخدام درجات من ألوان الهوية.
- تعتبر الوثيقة منتهية عندما يكون تاريخ انتهائها أسبق من تاريخ اليوم.
- ميّز الموظف المنتهية وثيقته بصرياً، واعرض علامة «منتهية» وتنبيهاً بلون تحذيري واضح.
- اعرض مؤشرين: إجمالي الموظفين، وعدد الهويات/الإقامات المنتهية.
- يظهر نموذج الإضافة أو التعديل كنافذة حوار؛ الإلغاء أو الضغط على خلفيتها يغلقها. بعد الحفظ، حدّث القائمة وأغلق النموذج.
- تعرض القائمة جميع الموظفين بما في ذلك من انتهت خدمتهم؛ استثناء الموظف المنتهي يخص مؤشرات الموظفين النشطين ومسير الرواتب.

### نموذج الإضافة والتعديل والتحقق

| الحقل                 | القاعدة                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| الاسم                 | مطلوب، من حرفين إلى 100 حرف بعد إزالة المسافات الطرفية                                          |
| الجنسية               | مطلوبة، «سعودي» أو «غير سعودي»                                                                  |
| رقم الهوية/الإقامة    | مطلوب، 10 أرقام بالضبط؛ يبدأ بـ `1` للسعودي و`2` لغير السعودي                                   |
| الآيبان               | مطلوب في النموذج؛ يبدأ بـ `SA` متبوعاً بـ 22 رقماً، مع قبول الأحرف اللاتينية الكبيرة أو الصغيرة |
| انتهاء الوثيقة        | مطلوب                                                                                           |
| المسمى الوظيفي        | مطلوب، حرفان على الأقل                                                                          |
| الأساسي والسكن والنقل | أرقام لا تقل عن صفر                                                                             |
| نسبة GOSI المخزنة     | رقم من 0 إلى 100                                                                                |

- القيمة الافتراضية لنسبة GOSI هي `9.75` للسعودي و`0` لغير السعودي، وتتغير تلقائياً عند تغيير الجنسية في نموذج الإضافة.
- عند التعديل، حمّل القيم الحالية كما هي ولا تستبدلها تلقائياً.
- اعرض رسالة التحقق بجانب الحقل الذي فشل، ولا تحفظ السجل عند وجود أخطاء.

## 7. وحدة مسيرات الرواتب

احسب لكل موظف غير منتهي الخدمة:

```text
الإجمالي = الراتب الأساسي + بدل السكن + بدل النقل
وعاء GOSI = الراتب الأساسي + بدل السكن
خصم GOSI = 9.75% من الوعاء للسعودي، و0 لغير السعودي
الصافي = الإجمالي - الخصومات
```

**تفصيل السلوك الحالي:** الحساب يستخدم نسبة ثابتة `9.75%` للسعودي ولا يقرأ حقل `gosiRate` المخزن. حقل النسبة موجود في بيانات الموظف والنموذج، لكنه لا يغير نتيجة المسير في هذه النسخة. حافظ على ذلك عند النقل إذا كان المطلوب مطابقة السلوك الحالي، أو اطلب قراراً منفصلاً قبل تحويله إلى نسبة قابلة للتخصيص.

تعرض الصفحة:

- إجمالي الموظفين المشمولين في المسير وإجمالي صافي الرواتب.
- تنبيهاً إذا كان هناك موظف بلا آيبان.
- ملاحظة بأن الحساب Demo وأن CSV لا يمثل ملف WPS الرسمي.
- جدولاً بالاسم، الآيبان، الإجمالي، الاستقطاعات، والصافي؛ مع مجاميع في ذيل الجدول.
- زر تصدير CSV يتعطل إذا لم توجد صفوف.

### تصدير CSV

- أعمدة الملف، بالترتيب: اسم الموظف، رقم الهوية/الإقامة، رقم الآيبان، العملة، إجمالي الأجر، الاستقطاعات، صافي الأجر.
- العملة `SAR`، والمبالغ رقمية بدقتين عشريتين.
- استخدم UTF-8 مع BOM لدعم النص العربي في برامج الجداول، واقتبس خلايا CSV واهرب علامات الاقتباس.
- امنع تفسير القيم النصية التي تبدأ بـ `=`, `+`, `-`, `@` أو مسافات/محارف تحكم على أنها صيغ جدول.
- اسم تنزيل واضح يتضمن سنة وشهر المسير.
- لا تسمّ الملف أو تصفه بأنه ملف مدد/WPS معتمد؛ هو ملخص CSV تجريبي.

## 8. وحدة إدارة العُهد

### لوحة العُهد

- تعرض عدد العُهد ذات الحالة `Active` وعدد العُهد ذات الحالة `Lost`.
- تعرض مجموعة العُهد لكل موظف مع النوع والوصف والرقم التسلسلي وتاريخ التسليم والحالة.
- يظل سجل العهدة محفوظاً عند تغيير حالته؛ لا تحذفه عند الإرجاع أو الفقد.

### إسناد عهدة

نموذج إسناد يتيح اختيار موظف من القائمة، نوع العهدة (سيارة/لابتوب/سلفة مالية)، الوصف، الرقم التسلسلي الاختياري، وتاريخ التسليم. القيمة الابتدائية للنوع لابتوب، وللتاريخ اليوم. يمنع الحفظ إذا لم يوجد موظف، أو كان الوصف فارغاً، أو لم يحدد التاريخ. تنشأ العهدة بالحالة `Active` وترتبط بمعرف الموظف.

### تغيير الحالة

- لكل عهدة نشطة زران: «استرجاع» لتصبح `Returned`، و«تسجيل فقدان» لتصبح `Lost`.
- بعد الانتقال من `Active`، لا تعرض أزرار التغيير في واجهة النسخة الحالية.
- قيم العرض: `Active` = مصروفة، `Returned` = مُسترجعة، `Lost` = مفقودة.

## 9. لوحة القيادة

### مؤشرات سريعة

- إجمالي الموظفين النشطين (كل من حالته ليست `Terminated`).
- نسبة التوطين = عدد السعوديين النشطين ÷ إجمالي الموظفين النشطين × 100. إذا لم يوجد موظفون، فالنسبة صفر. القيمة `50%` فأعلى تعرض بنبرة إيجابية، وما دونها بنبرة تنبيهية.
- عدد العُهد النشطة.
- عدد وثائق الهوية/الإقامة المنتهية أو التي تنتهي خلال 30 يوماً.

### الرسوم

- Donut: سعودي مقابل غير سعودي، من الموظفين النشطين.
- Bar: عدد العُهد لكل نوع (سيارات، أجهزة إلكترونية، سلف مالية). احتسب الأنواع من كل السجلات، بما فيها المسترجعة والمفقودة.
- استخدم ألوان الهوية للبيانات، وتسميات عربية، واتجاه RTL. حافظ على تباين النصوص والوسيلة الإيضاحية.

### التنبيهات والإجراءات

- جدول «إجراءات عاجلة» يعرض الموظفين ممن وثائقهم منتهية أو تنتهي خلال 30 يوماً، مع الاسم ونوع الوثيقة والتاريخ وزر يفتح إدارة الموظفين.
- رتّب القائمة حسب أقرب تاريخ انتهاء؛ المنتهي أولاً.
- قائمة «طلبات إخلاء الطرف المعلقة» تعرض فقط الموظفين `Terminated` ممن لديهم عهدة واحدة على الأقل ليست `Returned`، وتوضح عدد العُهد وأنواعها ورابط صفحة الإخلاء.
- رتّب KPI على شبكة 4 أعمدة للشاشات الواسعة، عمودين للمتوسطة، وعمود واحد للجوال.

## 10. وحدة إخلاء الطرف

- قائمة اختيار تعرض الموظفين الذين حالتهم `Terminated` فقط.
- بعد اختيار موظف، اعرض ملخص الموارد البشرية والعُهد المرتبطة بمعرفه.
- قسم الموارد البشرية يوضح عدد أيام الإجازة غير المعوضة. الصفر أو غياب القيمة يعني عدم وجود أيام مستحقة غير معوضة.
- قسم العُهد يعرض كل عهد الموظف وحالتها.
- زر «إصدار مخالصة نهائية» مفعّل فقط إذا كانت كل العُهد المرتبطة بالموظف `Returned`.
- إذا وجدت عهدة `Active` أو `Lost`، عطّل الزر واعرض سبب المنع بوضوح واطلب تسوية العهدة.
- الموظف الذي لا يملك عُهداً مؤهّل من ناحية العُهد، لأن شرط التحقق على قائمة فارغة يعتبر مستوفى.
- ظهور أيام إجازة غير معوضة لا يعطّل الزر في السلوك الحالي؛ تعرض المعلومة للمراجعة فقط. لا تضف بوابة منع جديدة من دون قرار منتج.
- عند الإصدار، اعرض رسالة نجاح Demo، وامنع إصدار المخالصة مرة أخرى للموظف نفسه أثناء الجلسة.

## 11. تعليمات الهوية البصرية: إثراء الخير

هذه التعليمات مصدرها دليل الهوية المرفق، مع تفضيل المستخدم الأحدث بتخفيف الزخرفة والابتعاد عن كثرة الـBanners.

### الشعار والنمط

- استخدم شعار «إثراء الخير» أو العلامة الهندسية المعتمدة المتاحة في أصول المشروع. حافظ على النسب والمساحة الآمنة حوله؛ لا تمدده أو تدوّره أو تعِد رسمه كنص بديل.
- إذا لم تتوفر نسخة أصلية مناسبة رقمياً، اطلب ملف شعار SVG/PNG عالي الجودة بدلاً من قص شعار منخفض الجودة من صورة PDF للإنتاج النهائي.
- النمط الأساسي يتكون من أشكال هندسية مثلثة ومعينات متكررة مشتقة من العلامة. استخدمه كعلامة مائية خفيفة أو تفصيل صغير ونادر، لا كخلفية كثيفة وراء النصوص.

### لوحة الألوان

| الدور           | اللون المرجعي                        |
| --------------- | ------------------------------------ |
| أخضر مزرق أساسي | `#008186`                            |
| فيروزي          | `#00B5A4`                            |
| ذهبي رملي       | `#C19F79`                            |
| خلفية هادئة     | أبيض أو أبيض مائل لدرجة محايدة فاتحة |

- أنشئ درجات أفتح وأغمق من الألوان المرجعية للحدود والأسطح والنصوص.
- اجعل الأخضر المزرق هو اللون الأساسي للأزرار والعناوين النشطة والروابط الأساسية.
- استخدم الفيروزي للتأكيدات الثانوية والرسوم، والذهبي الرملي كلمسة صغيرة مثل خط أو مؤشر أو تفصيل بالشعار.
- لا تضع عدة ألوان مشبعة بجوار بعضها بلا مساحة محايدة. لا تستخدم تدرجاً داكناً كبيراً أو Banner في كل صفحة.
- اجعل صفحات المحتوى على خلفية محايدة هادئة، والبطاقات بيضاء بحدود وظلال خفيفة. استخدم لوناً أحمر/وردياً للحالات التي تعني خطراً فعلياً مثل انتهاء الوثيقة أو فقدان عهدة فقط.
- راعِ تباين WCAG العملي، خصوصاً النص فوق الأزرار والخلفيات الملونة. لا تضع نصاً أبيض صغيراً فوق الذهبي الرملي.

### الخطوط والأيقونات

- الخط العربي الأساسي في الدليل: **FF SHAMEL Family**. يتضمن الدليل بدائل مثل **GE SS Two** و**Montserrat Arabic** عند تعذر استخدام الخط الأساسي.
- استخدم خط الهوية إذا كان ملفه مرخصاً ومتاحاً في المشروع. وإلا استخدم بديلاً عربياً واضحاً ومقروءاً، مثل Cairo أو Tajawal عند توفرهما، مع توحيد الخط على مستوى النظام.
- استخدم عائلة أيقونات خطية واحدة وبأحجام متناسقة. لا تستخدم Emojis ولا تمزج رموز Unicode عشوائية مع الأيقونات.

### أسلوب تخطيط الصفحات

- لا تجعل كل صفحة تبدأ بلوح عريض ملوّن. استخدم عنواناً بسيطاً على الخلفية المحايدة: اسم الصفحة، وصف قصير، وخط أو علامة هوية صغيرة.
- اجعل اللون القوي لمواضع التفاعل المهمة فقط، مثل زر الإجراء الأساسي وحالة الرابط المحدد.
- اعتمد المساحات البيضاء والمحاذاة المتسقة والحدود الخفيفة، واحتفظ بالنمط الهندسي لتفاصيل محدودة.
- دعم RTL كامل في ترتيب التنقل، العناوين، الجداول، الحقول، القوائم والرسوم، مع إبقاء IBAN والأرقام والمعرفات اللاتينية باتجاه LTR عند الحاجة.
- اجعل الجداول قابلة للتمرير أفقياً على الشاشات الصغيرة، والنوافذ المنبثقة ملائمة لارتفاع الجوال.
